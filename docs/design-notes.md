# 从 V1 到 V2：先让计划能被检查

## 起点
首版已经有“检查—整理—导出”的方向、共享数据与材质规则。复核首版源码发现，报告只有全局布尔验证字段，规则版本仍是 1.0，安装说明依赖手动复制；这些是文档与可使用性上的具体缺口。

## 本次做了什么
- 把检查模式、对象身份、批次外重名和路径碰撞写成 V2 计划约定。
- 增加无 Blender 依赖的计划检查器，以合成数据覆盖名字交换、不同命名空间、越界目标、目录穿越和覆盖策略。
- 报告改为每项记录生成、回读、外观状态；一个失败项不能被其他成功项掩盖。
- 增加固定版本的 Agent 安装说明、升级备份与回退步骤。

## 实际遇到的设计难点
**名字不是身份。** 如果按名字追踪对象，名字改掉后就无法可靠恢复。因此计划把稳定 ID 与名称分开；只检查任务也不为生成 ID 去改资产。

**同名不一定冲突。** 对象与材质可以同名，同一命名空间的 A/B 互换也有合法实现。检查器既要发现占用，又不能把合法置换挡掉。

**文件生成不代表交付合格。** 回读和外观需要不同证据。V2 将它们拆为独立状态，保留未验证状态。

## 当前证据边界
本次验证对象是规则包、示例计划与检查脚本，不包含生产工程批量执行，没有制作演示或宣称节省了多少工时。今后在实际资产上使用时，记录输入、版本和结果，再针对真实失败修订对应规则。
