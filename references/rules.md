# 资产规则参考

## 命名

项目未提供规则时，可提出 `SM_<语义>_<编号>` / `MAT_<语义>` 作为静态资产示例。骨骼、灯光、相机、碰撞体、LOD 与引擎专用名称应使用各自约定，不强套静态网格规则。

- `NAME-01`：批次内与批次外同类型对象的目标名称冲突。Blender 对象、集合、网格、材质是不同命名空间，分别检测。
- `NAME-02`：禁用字符、过长名称或目标平台不兼容名称。以明确的交付规范为判断依据。
- `NAME-03`：共享数据、库链接或字符串引用。重命名可能影响驱动表达式、脚本、导出映射，先检查引用。
- `NAME-04`：稳定性。相同输入 / 规则再次执行应无额外编号变化；遍历顺序不能决定资产身份。

## 材质与贴图

- `MAT-01`：可渲染网格无材质 / 空材质槽。可能是白模项目的有意设置，先根据目标分类，不直接补材质。
- `MAT-02`：材质槽索引与面分配异常，记录对象及槽位。不要仅以槽名存在判定绑定成功。
- `TEX-01`：外部图像文件不存在。先解析 Blender `//` 相对工程路径、库来源与打包状态；打包图片不依赖原磁盘文件存在。
- `TEX-02`：UDIM、序列、电影、渲染结果与生成图片采用不同规则。不要对 `<UDIM>` 字面路径执行一次 exists 就判定全部缺失。
- `TEX-03`：图像通过材质组间接引用时递归检查，并对循环引用去重；未使用节点与实际着色路径区分标记。
- `MAT-03`：目标格式可能不支持的节点、程序纹理或混合模型。列出限制和可选烘焙方案，未经授权不自动烘焙或替换。
- `COLOR-01`：颜色空间仅提出有依据的警告。基础色与法线 / 粗糙度等数据纹理通常用途不同，但使用链路、通道打包和项目色彩管理可能改变判断；不能只根据文件名修改。

## 导出

- `EXP-01`：格式、引擎、资产边界和目录明确。
- `EXP-02`：目标碰撞可预见；绝不将不同资产写入同名文件后只保留最后一份。
- `EXP-03`：需要父级、骨骼或依赖对象时纳入交付边界，避免选择网格但漏出绑定。
- `EXP-04`：检查纹理路径、文件完整性与重导入状态。数量差异按实例、分件和格式规则解释。
- `EXP-05`：拓扑、UV、单位、法线和外观不会因“文件存在”自动判定通过。
